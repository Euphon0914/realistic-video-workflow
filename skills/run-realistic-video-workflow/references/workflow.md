## 1. 工作流目标

用户只需提交现有资料并要求启动或继续项目。系统自行完成资料识别、需求推导、脚本、视觉开发、分镜、提示词、生成编排、质量核查、后期和归档；仅在5个固定审核闸门或确有必要的异常节点请求用户参与。

本流程不预设项目类型。适用于纪录片、人物故事、品牌或产品片、文化旅游、教育科普、公益内容、活动短片、社交媒体短视频及其他真人写实视频。

## 2. 固定原则与非固定内容

### 固定原则

- 统一为真人质感写实风格：真实皮肤、五官、人体结构、表情、衣物、物理接触和运动惯性。
- 使用符合真实摄影的焦段、景深、机位、光线、材质、环境和声音。
- 克制调色与特效，避免塑料皮肤、游戏CG感、过度磨皮、科幻发光和不必要的奇观化。
- 所有事实、身份、产品功能、地点和授权均可追溯。
- 已审核内容不覆盖，修改以版本方式保存。

### 每个项目重新推导

- 题材、受众、传播目标和叙事形式；
- 地域、年代、场景、品牌和文化语境；
- 时长、画幅、分辨率、帧率、语言、字幕和声音策略；
- 角色、产品、道具、服装和场地；
- 使用的生成模型、组合方式和后期策略。

不得自动继承其他项目的视觉风格、地点、品牌、人物、产品、旁白语言或技术规格。

## 3. 用户提交资料

资料无需严格命名。系统负责分类、建立索引和标记缺口。

| 类别 | 可提交内容 | 用途 |
|---|---|---|
| 项目与主题 | 背景说明、目标、受众、发布渠道、核心信息 | 推导项目简报与叙事形式 |
| 主体资料 | 人物、机构、事件、地点、作品或议题资料 | 建立事实与故事基础 |
| 人物 | 正侧面照片、身份、年龄感、服装、采访、授权 | 角色锁定与人物一致性 |
| 产品与物件 | 多角度图片、规格、功能、操作视频、使用限制 | 外形、尺度、动作和功能核查 |
| 场地 | 外景、室内、平面关系、实拍视频、地域参考 | 场景、机位和空间连续性 |
| 内容来源 | 现有脚本、采访、文章、研究、旁白、字幕 | 脚本与事实引用 |
| 视觉资料 | 品牌手册、Logo、参考影片、喜欢或排斥的风格 | 项目专属视觉方向 |
| 合规资料 | 肖像、版权、商标、保密和行业限制 | 决定素材能否使用 |
| 交付要求 | 时长、画幅、语言、平台、文件格式 | 成片与衍生版本规划 |

资料不足时先从现有文件推导，不逐项追问。无法确认且会改变项目方向、事实准确性、授权或成本的问题，集中进入Gate 1。不得虚构事实、产品参数、身份或授权。

## 4. 项目结构与状态

标准项目目录：

```text
project/
├── 00_intake/
│   └── uploads/
├── 01_brief/
├── 02_script/
├── 03_locked-assets/
├── 04_visual-bible/
├── 05_storyboards/
├── 06_generation-plan/
├── 07_generated-video/
├── 08_postproduction/
├── 09_delivery/
└── .workflow/
    ├── workflow-state.json
    ├── intake-manifest.json
    ├── approval-log.md
    └── audits/
```

阶段状态：`pending → running → needs_review → approved → completed`。

异常状态：

- `needs_revision`：用户要求修改；
- `blocked`：缺少关键资料、授权、能力或外部条件；
- `failed`：执行失败且无法在既定设计内恢复。

启动时先验证状态。恢复时从最早的未完成或被失效阶段继续，不重复执行已批准阶段，不重复询问已保存的决定。

状态文件与manifest的公开字段、阶段顺序和生产授权规则以`state-schema.md`为准。遇到不支持的schema版本时必须停止并要求显式迁移，不猜测字段含义。

## 5. 自动执行阶段与审核闸门

### 阶段1：资料接收与项目简报

自动执行：

- 扫描、去重、哈希登记并分类资料；
- 建立事实来源表、授权状态、冲突项和缺失资料清单；
- 推导项目名称、题材、受众、目标、叙事形式和交付规格；
- 对无法确定的规格给出推荐值及理由。

产出：项目简报、资料清单、事实表、缺失项和风险表。

**Gate 1：项目简报审核**

集中确认项目方向、事实边界、交付规格、授权风险和少量高影响问题。批准结果写入状态，后续不再重复询问。

### 阶段2：脚本与叙事

自动执行：

- 根据资料选择纪录、人物、说明、剧情化或混合叙事；
- 生成幕结构、脚本、旁白、字幕、镜头时长和核心动作；
- 建立事实—脚本文句追溯；
- 检查旁白速度、时长、重复信息和不可证实表述。

产出：脚本、旁白、字幕、时间码、镜头表和事实追溯表。

**Gate 2：脚本审核**

确认故事方向、事实、表达口径、语言和时长。批准后锁定脚本版本。

### 阶段3：人物、物件与视觉锁定

自动执行：

- 建立人物参考索引和角色板；
- 建立产品、道具或作品的型号/版本/功能约束；
- 从项目资料推导专属视觉圣经；
- 制作少量风格样片并检查真人写实基线；
- 标记缺少官方依据或不适合特写的资产。

产出：角色板、资产索引、知识与约束卡、视觉圣经、样片和禁用项。

**Gate 3：视觉资产审核**

确认人物身份、服装、产品或物件、场景、地域、色彩、光线、材质和摄影语言。批准资产成为后续最高优先级参考。

### 阶段4：分镜、生成单元与审计

自动执行：

- 生成镜头级分镜参考图；
- 建立复用矩阵，避免无意义重复生图；
- 按模型时长、叙事、人物、空间和动作关系合并生成单元；
- 为每个生成单元编写可独立提交的完整提示词；
- 逐段执行提示词—参考图一致性审计；
- 识别多人物、多产品、多硬切、复杂手部和物理动作等高风险段。

产出：分镜、镜头表、复用矩阵、生成映射、提示词、素材职责表、审计矩阵和生产预算/任务清单。

**Gate 4：生成前审核与生产授权**

确认分镜、生成单元、引用素材、审计结论、高风险试产顺序及正式生成范围。批准前不得启动付费或消耗额度的正式生成。

### 阶段5：试产、批量生成与QA

自动执行：

- 优先试产高风险片段；
- 试产通过后批量生成普通片段；
- 保存任务ID、模型设置、素材连接、提示词、结果和重试记录；
- 核查人物、场景、产品/道具、动作、机位、声音、稳定尾帧和跨镜污染；
- 在已批准设计内优先简化动作、减少引用或做局部修正。

试产失败但可在批准范围内修复时自动迭代。连续失败、需要更改已批准设计或产生额外大批量消耗时，作为异常节点暂停。

### 阶段6：后期、成片与归档

自动执行：

- 按目标时间码剪辑；
- 加入旁白、字幕、现场声、音乐或无音乐策略；
- 完成调色、混音、字幕安全区、技术检查和平台适配；
- 生成QA报告、修改摘要、限制说明和完整归档包。

**Gate 5：成片审核**

提交成片预览、字幕旁白、QA报告和修改清单。批准后输出母版、衍生版本及项目归档。

## 6. 提示词—参考图一致性审计

每个生成单元必须逐项检查，不抽样：

| 维度 | 核查内容 |
|---|---|
| 场景 | 地点、空间结构、时间、天气、光线、材质和氛围是否对应 |
| 人物 | 数量、身份、服装、站位、朝向、视线、表情和手部状态是否对应 |
| 动作 | 初始状态、动作顺序、物体接触和结束状态能否从参考图自然启动 |
| 产品/物件 | 外形、版本、尺度、功能、承载关系和使用方式是否正确 |
| 视角 | 景别、构图方向、人物轴线和主体前后关系是否一致 |
| 机位 | 高度、焦段、俯仰角、拍摄方向和安全距离是否与空间兼容 |
| 运镜 | 推、拉、摇、移或固定是否具有空间余量，是否存在互斥描述 |
| 素材职责 | 每张`@图片N`是否职责单一明确，是否错误继承无关内容 |
| 跨镜连续性 | 硬切后是否清除上一镜人物、物件、空间和声音 |
| 禁止项 | 是否覆盖身份漂移、肢体畸形、物理错误、文字乱码、Logo和水印等风险 |

审计记录格式：

`生成段｜叙事镜头｜引用图片｜核查结论｜冲突项｜处理动作｜复核状态`

结论限定为：

- 通过；
- 修改提示词；
- 修改或替换参考图；
- 重组生成单元。

任何冲突未关闭时，不得提交该段生成。

## 7. 异常暂停与修改传播

仅在以下情况于固定闸门外暂停：

- 事实、人物身份、产品功能或地点资料相互矛盾；
- 缺少肖像、版权、商标或保密授权；
- 必需能力或生成服务不可用；
- 变更会推翻已批准的上游设计；
- 即将产生未批准的额外消耗；
- 无法在不误导观众的情况下继续。

修改传播遵循最小失效原则：

- 修改项目简报：失效所有下游；
- 修改脚本或时长：失效分镜、生成计划、提示词和后期；
- 修改人物、物件或视觉资产：只失效引用该资产的分镜和视频；
- 修改提示词：只失效对应生成单元及其后期片段；
- 修改字幕或混音：不重做已批准画面。

## 8. 可获得的交付资料

| 阶段 | 交付资料 |
|---|---|
| 项目定义 | 项目简报、资料清单、缺失项、事实与授权风险表 |
| 脚本 | 幕结构、脚本、旁白、字幕、时间码、镜头表、事实追溯表 |
| 视觉开发 | 角色板、资产索引、约束卡、视觉圣经、样片和禁用项 |
| 分镜与生成 | 分镜图、复用矩阵、生成映射、完整提示词、素材职责表 |
| 生成前审计 | 提示词—参考图审计矩阵、冲突与修正记录、任务清单 |
| 视频生产 | 分段视频、任务状态、重试记录、视频QA报告 |
| 后期交付 | 成片母版、平台版本、字幕、旁白、混音说明和完整归档包 |

## 9. 可选集成职责

核心资料整理、状态机、审计和审核流程不依赖下列能力。只在当前阶段确有需要时检测；缺失时按`integrations.md`生成平台中立交付物或暂停在对应生产边界。

| Skill | 职责 |
|---|---|
| `imagegen` | 角色板、视觉样片、分镜参考图和局部单点修正 |
| `libtv-cli` | 画布、素材上传、节点连接、提示词、任务和结果管理 |
| `seedance-prompt-zh` | 多模态视频提示词、引用职责、时间轴、动作、机位、声音和负面约束 |
